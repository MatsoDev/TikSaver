# Tiksave

A single-user TikTok streak saver. Tiksave sends a preset message to one chosen
TikTok contact at a daily time you choose, even when your phone or laptop is
off.

## How it works

1. **Vercel (Next.js 14 App Router)** hosts the admin UI and the API.
2. **cron-job.org** calls `GET /api/tick` once a minute with the
   `x-cron-secret` header. The tick endpoint looks for jobs that are due and
   dispatches the worker.
3. **GitHub Actions** runs the Playwright worker in `/worker` on demand
   (`workflow_dispatch`). The worker opens TikTok with the stored session,
   sends the message, and reports the result back to the app.
4. **Neon Postgres** (via `drizzle-orm`) stores jobs, the encrypted TikTok
   session, and run logs.
5. **Telegram Bot API** notifies you about every send attempt.

The device that schedules the job does not need to be online: the schedule lives
in Postgres, the trigger lives in cron-job.org, and the browser lives in GitHub
Actions.

## Stack

| Layer      | Choice                                              |
| ---------- | --------------------------------------------------- |
| App        | Next.js 14 (App Router), TypeScript, Tailwind CSS    |
| Database   | Neon Postgres + `drizzle-orm` (`neon-http` driver)   |
| Worker     | Node + Playwright in `/worker`, GitHub Actions       |
| Scheduler  | cron-job.org -> `GET /api/tick`                      |
| Alerts     | Telegram Bot API                                     |

## Environment variables

Copy `.env.example` to `.env.local` for local development and set the same keys
in the Vercel project settings. Never commit real values.

| Variable             | Purpose                                                        |
| -------------------- | -------------------------------------------------------------- |
| `DATABASE_URL`       | Neon Postgres connection string (pooled).                      |
| `ADMIN_PASSWORD`     | Password for the single-user admin UI.                         |
| `ENCRYPTION_KEY`     | 32 random bytes, base64 encoded. Encrypts the TikTok session.  |
| `CRON_SECRET`        | Shared secret expected in `x-cron-secret` on `/api/tick`.      |
| `GITHUB_TOKEN`       | Fine-grained token with `Actions: write` on the repo.           |
| `GITHUB_REPO`        | `MatsoDev/TikSaver`.                                            |
| `TELEGRAM_BOT_TOKEN` | Bot token from @BotFather.                                     |
| `TELEGRAM_CHAT_ID`   | Your chat id with the bot.                                     |

Generate a key with:

```bash
node -e "console.log(require('crypto').randomBytes(32).toString('base64'))"
```

## Database

The schema lives in `db/schema.ts` and covers:

- `jobs` - one row per scheduled message: target, message, `HH:MM` send time,
  IANA timezone, jitter window, enabled flag, and last-run bookkeeping.
- `sessions` - the encrypted TikTok cookies (one row is used).
- `logs` - every run attempt with status, detail, and an optional screenshot URL.

Commands:

```bash
npm run db:generate   # create SQL migrations in ./drizzle
npm run db:migrate    # apply migrations to DATABASE_URL
npm run db:push       # push schema directly (dev shortcut)
npm run db:studio     # browse data
```

`db/index.ts` creates the Neon client lazily, so `next build` succeeds even when
`DATABASE_URL` is not present (for example on a fresh clone).

## Local development

```bash
npm install
cp .env.example .env.local
npm run db:migrate
npm run dev
```

Open http://localhost:3000.

## Decisions

- **Next.js pinned to 14.2.35.** It is the latest patched 14.x release; earlier
  14.2.x builds have a known security advisory.
- **`@neondatabase/serverless` with the `neon-http` driver.** It works on
  Vercel's edge/serverless runtime and over plain HTTP from GitHub Actions, so
  the same schema and client are usable in both places.
- **Lazy database initialization.** Importing `db/index.ts` never throws, which
  keeps builds and the public landing page working before secrets are set.
- **UUID primary keys generated by Postgres** (`gen_random_uuid()`), available
  in every current Neon project without extra extensions.
- **`send_time` stored as `text` in `HH:MM`.** It keeps the user's wall-clock
  intent explicit; the timezone column decides the actual instant.
- **`jitter_minutes` default 5.** Sends are spread over a small random window
  so they do not look mechanically exact.
- **`last_run_date` is a `date`.** It prevents double-sending on the same local
  day and is easy to compare regardless of server timezone.
- **Secrets never committed.** `.env`, `.env.*` (except `.env.example`),
  cookie files, and screenshots are ignored.
